# Meeting Notes Studio（会议纪要工坊）

> 项目英文名：**Meeting Notes Studio**　｜　包名：`meeting-notes-studio`　｜　程序位于本文件夹下

## 📖 项目介绍

**会议纪要工坊是一个跑在你自己电脑上的「录音整理流水线」。** 你把一场会议、一节课或一段访谈的录音丢进文件夹，它就把这段声音依次过三遍手，产出三份可以互相印证的 Markdown 文档：

```
会议录音.mp3  ──►  ① 转写原文  ──►  ② 润色稿  ──►  ③ 会议纪要
                    （带时间点，         （口语转书面，      （结论 / 议题 /
                      一字不落的底稿）      去掉语气词）        待办 / 风险）
```

### 它解决什么问题

录音转文字的工具不少，但真要用起来通常会卡在三件事上：

1. **转写结果不能直接用** —— 满屏「嗯、啊、那个」，看一遍比听一遍还累。
2. **转完了还得二次加工** —— 想拿到结论和待办，要再手工整理一遍。
3. **长音频很麻烦** —— 一小时的会，往往是几十上百 MB，要切、要等、还容易超时失败。

这个工具把这三步串成一条自动流水线：**你只准备录音，剩下的三份产物自己长出来**。

### 它是怎么工作的

每个环节都可以挂一个不同的模型，各司其职：

| 环节 | 做什么 | 可接什么 |
| --- | --- | --- |
| **① 转写** | 音频 → 带时间点的逐段文字 | OpenAI 兼容转写接口 / 阿里云百炼 Paraformer / Gemini 多模态 / 任意多模态大模型 |
| **② 润色** | 口语 → 书面语，保留专有名词与数字，去掉语气词 | 任意 OpenAI 兼容或 Gemini 原生对话模型 |
| **③ 纪要** | 按固定骨架提炼：会议信息 / 一句话结论 / 核心议题与结论 / 待办事项 / 风险 | 同上，可换成自定义模板 |

**三个环节的模型全都由你自己提供**，工具本身不内置任何账号、不代收任何费用、不向任何服务器上传隐私数据。

### 设计上的几个坚持

- **🔒 数据不出本机。** 服务只监听 `127.0.0.1`，每次启动生成随机访问令牌，界面上的密钥永远是掩码。录音、转写、纪要全部留在你的硬盘上，只在你配置模型接口时才会把那一段音频发给对应服务商。
- **📦 零依赖。** 没有 `npm install`，没有构建步骤，没有 `node_modules`。整个程序就是几十个 `.mjs` 文件加一个 HTML 页面。
- **🖱️ 双击即用。** 双击 `start.bat`，浏览器自动打开，全程图形界面操作，不需要敲命令。
- **📁 尊重你的文件系统。** 不用手动上传——程序直接读你指定的「工作区文件夹」，产物也写回文件夹里，文件名带时间戳，同名自动加序号，永不覆盖旧文件。
- **⏱️ 长音频不怕。** 一小时的录音可以走百炼大文件通道，或由程序自动找 `ffmpeg` 切片转写再把时间戳拼回来。
- **🔁 可中断可续跑。** 任务跑到一半关掉程序，重启后能从上次完成的步骤接着跑，已完成的部分有缓存、不重复计费。

### 适合谁用

- 要整理**会议、评审、访谈**记录，又不想把内容交给第三方云笔记的人
- 想把**课程、讲座、播客**录音转成可检索文字稿的学生和内容创作者
- 关心**数据主权**、希望整个流程都在本地完成的小团队

### 现在就能试

不需要任何 API Key：装好 Node.js 20+，双击 `start.bat`，点「**用模拟模型试用**」，就能完整体验一遍从录音到三份产物的流程。

## ✨ 核心特性

- 本地运行，双击 `start.bat` 就能用浏览器操作，**不需要 `npm install`、不需要构建、没有任何第三方依赖**。
- 三个模型槽位（转写 / 润色 / 纪要）全部用你自己的账号配置；配置只保存在本机 `data/config.json`。
- 支持三种协议：**OpenAI 兼容**（chat/completions + audio/transcriptions）、**Google Gemini 原生**、**阿里云百炼 Paraformer 异步转写**（含 OSS 临时上传）。
- 文件不用手动上传：程序直接读取**工作区文件夹**里的文件，产物默认就交付回该工作区。

## 一、快速开始

1. 确认本机有 **Node.js 20 或更高版本**（`node --version`）。没有就去 <https://nodejs.org/> 装一个。
2. 进入 `meeting-notes-studio` 文件夹，双击其中的 `start.bat`。控制台会打印地址并自动打开浏览器（默认 <http://127.0.0.1:8787/>）。
3. 第一次使用建议先点「**用模拟模型试用**」：不联网、不花钱，把整个流程跑一遍看产物长什么样。
4. 正式使用：进「设置」依次配置 **转写模型**、**润色模型**、**纪要模型**，每个都可以点「测试连接」验证。
5. 到「工作区」添加一个文件夹，把音频/文本放进去，然后「新建任务」。第 ③ 步的文件**可以多选**：勾几个就并行创建几个任务，提交后自动进入「并行任务」日志墙。

关闭控制台窗口（或在窗口里按 `Ctrl+C`）即可停止服务。

## 二、三个模型怎么配

### 转写模型（任务一：语音转文字）

「接入方式」有五种，选哪种决定后续字段：

| 接入方式 | 适合 | 必填字段 | 时间戳 |
| --- | --- | --- | --- |
| OpenAI 兼容 · 语音转写接口 | OpenAI whisper、任何兼容 `/audio/transcriptions` 的服务 | 接口地址、API Key、模型名 | 精确（接口返回逐段起止时间） |
| 阿里云百炼 · Paraformer 异步转写 | 中文会议、小时级长音频 | 接口地址（默认 `https://dashscope.aliyuncs.com`）、API Key、模型名（如 `paraformer-v2`） | 精确（句级） |
| Google Gemini · 音频理解 | 想用一个多模态模型搞定全部 | 接口地址（默认 `https://generativelanguage.googleapis.com/v1beta`）、API Key、模型名（如 `gemini-2.5-flash`） | 估算（模型标注） |
| OpenAI 兼容 · 多模态大模型 | qwen-omni、gpt-4o-audio 这类能听音频的对话模型 | 接口地址、API Key、模型名 | 估算（模型标注） |
| 内置模拟模型 | 先跑通流程 | 无 | 假数据 |

**多模态开关**：如果转写槽位选的是「多模态」类模型，把「这是多模态大模型，可以兼任润色与纪要」勾上，那么**润色/纪要留空时会自动用它**（任务详情里会标注「复用转写模型」）。选专用转写接口时这个开关不可用，润色与纪要必须单独配置。

### 润色模型 / 纪要模型

两个槽位都是文本模型，支持「OpenAI 兼容」与「Gemini 原生」两种协议。常用填法：

- DeepSeek：`https://api.deepseek.com/v1`，模型 `deepseek-chat`
- OpenAI：`https://api.openai.com/v1`，模型 `gpt-4o-mini` 等
- 通义/百炼兼容模式：`https://dashscope.aliyuncs.com/compatible-mode/v1`，模型 `qwen-plus`
- 硅基流动：`https://api.siliconflow.cn/v1`，模型名按平台文档
- 本地 LM Studio / vLLM：`http://127.0.0.1:1234/v1` 之类，模型名填服务里的名字
- Gemini 原生：`https://generativelanguage.googleapis.com/v1beta`，模型 `gemini-2.5-flash`

只填域名（如 `api.deepseek.com`）程序会自动补 `/v1`。

润色模型可调：温度、每块字数、三条润色要求（口语转书面 / 保留专有名词数字 / 去掉语气词）、额外要求提示词。
纪要模型可调：温度、每块字数、纪要结构（默认模板或自定义提示词）、是否在纪要里引用时间点、输出语言。

## 三、任务是怎么跑的

### 流程与输入类型

勾选流程（至少一项），程序据此决定要什么输入：

| 勾选的流程 | 需要提供的文件 | 产物 |
| --- | --- | --- |
| 转写 + 润色 + 纪要 | 音频 | 转写原文、润色稿、纪要 |
| 转写 + 纪要 | 音频 | 转写原文、纪要 |
| 只转写 | 音频 | 转写原文 |
| 润色 + 纪要 | 文本 | 润色稿、纪要 |
| 只润色 / 只纪要 | 文本 | 对应一份 |

规则很简单：**勾了「转写」就必须给音频，否则给文本**。

- 音频支持：mp3 / wav / m4a / aac / flac / ogg / opus / wma / amr，以及 mp4 / mov / mkv / webm 等视频（会按音频处理）。
- 文本支持：txt / md / srt / vtt / text / log。srt/vtt 会自动解析出纯文本（并保留时间段供纪要引用）。

### 多选文件与并发

- **文件可多选**：新建任务第 ③ 步里每个文件前都是勾选框，右上角有「全选 / 取消全选 / 清空选择」，并实时显示「已选 N / 总数」。**勾几个文件就创建几个任务**，一个文件一个任务、各自一套产物，互不干扰。
- **并发执行**：默认同时跑 **3** 个任务（可在「设置 → 通用 → 同时运行的任务数」调到 1–5）。多选超过并发数时，其余任务排队，前一个结束后自动补位；新建任务页会提示「先同时跑几个、其余排队」。
- **并行日志页**：提交后会自动跳到 `#/batch/...` 的「并行任务」页，**每个任务一张卡片**：各自的进度条、当前阶段、实时日志窗口（滚动跟随），完成后可直接看产物清单、打开所在位置、进详情页。页面顶部有「运行中 N / 总数」「全部取消」「打开交付文件夹」。
- **随时回到日志墙**：首页只要有排队/运行中的任务，就会出现「查看实时日志」按钮，一键打开这些任务的日志墙。
- 并发意味着**同一个模型账号会被同时打 N 份请求**；如果遇到限流（429），把并发调小或换更宽松的模型即可。

### 纪要的输入来源

- 如果这次跑了润色 → 纪要基于**润色稿**（信息最干净）；
- 只跑了转写 → 基于**转写原文**；
- 只给文本 → 基于**你提供的文本**。

### 工作区与交付区

- **工作区**：一个本机文件夹。新建任务时必须选一个工作区，并只能从**该工作区内的文件**里挑输入（含最多 3 层子目录）。
- **添加方式**：点「添加工作区」「选择文件夹」时，会弹出**系统原生的文件夹选择窗口**：
  - Windows：资源管理器同款的**新式「选择文件夹」窗口**（走 COM 的 `IFileOpenDialog`，不是老式的树形对话框）。窗口标题会写明你正在选什么，并直接定位到当前工作区/交付区路径。
  - **清晰度**：窗口按屏幕缩放比例原生渲染（脚本宿主会先切成 per-monitor DPI 感知），125%/150% 缩放下文字不会发虚。
  - **前置**：窗口带一个 1×1 的置顶隐藏窗体作 owner，会出现在浏览器窗口前面，不用去任务栏找。
  - macOS：`choose folder` 窗口；Linux：`zenity` 目录选择器。
  - 选完自动回填路径；点「取消」则什么都不改。
  - 如果系统里拿不到原生窗口（例如没有 zenity 的 Linux，或 PowerShell 被策略限制），会自动回退到程序内置的目录浏览器，并在设置 → 通用里显示当前用的是哪种方式。
- **删除 / 改名**：新建任务页的「删除工作区」和「工作区」页每行的「删除」都能移除工作区，点「编辑」可以改名或设置默认交付区。**删除只是取消登记，不会删除文件夹里的文件，历史任务与产物也都会保留**；移除后不能再用它建新任务。
- **交付区**：默认就是工作区；也可以在新建任务时另选一个文件夹。产物文件名形如：

```
产品周会_20260214-1530_转写原文.md
产品周会_20260214-1530_润色.md
产品周会_20260214-1530_纪要.md
```

同名已存在时自动加 ` (2)`、` (3)`，不会覆盖旧文件。

### 产物长什么样

`转写原文.md`：

```md
# 转写原文：产品周会.mp3

- 生成时间：2026-02-14 15:30
- 模型：whisper-1 · OpenAI 兼容
- 时间戳：精确（转写接口返回的逐段起止时间）
- 来源：产品周会.mp3，12.40 MB，时长约 43 分 12 秒
- 分段数：312 段
- 字数：8,731

## 逐段原文
[00:00:00.0 - 00:00:05.3] 大家好，今天这次会议主要讨论三件事。
[00:00:05.3 - 00:00:11.8] 第一是下个季度的产品排期……
```

`润色.md`：标题 + 元信息 + 分段正文。
`纪要.md`：标题 + 元信息 + 固定骨架（会议信息 / 一句话结论 / 核心议题与结论 / 待办事项 / 风险与待确认问题），可在设置里换成自己的模板。

时间戳的可信度：走 ASR 接口（OpenAI 兼容转写、百炼 Paraformer）是**精确**的；走多模态模型（Gemini、qwen-omni 等）是模型自己标注的**估算**值，产物头部会写明。接口完全不返回分段时会标「不可用」，此时原文以整段形式输出。

### 删除任务

任务列表每行右侧有「删除」按钮：

- **只删记录**（默认）：任务从列表消失，程序内部的缓存与运行日志一并清理，但已经交付到文件夹的 `.md` 产物**原样保留**。
- **连产物一起删除**：任务有产物时才会出现这个选项，会一并删掉该任务记录过的那几个 `.md` 文件（不可恢复），其他文件不动。
- **运行中的任务不能直接删**：先点「取消任务」或等它跑完，再删除。

## 四、长音频怎么办

- **百炼 Paraformer**：单文件可到 1GB，小时级录音直接用这个最省心。
- **Gemini**：内联音频上限约 15MB。
- **OpenAI 兼容转写接口**：单次上限 25MB。超出时，如果系统里能找到 `ffmpeg`，程序会**自动切片**（10 分钟一段，转 16k 单声道 mp3）逐段转写，再把时间戳偏移合并回来；找不到 `ffmpeg` 会给出明确提示。
- 「设置 → 通用」里能看到 ffmpeg 是否可用。

想启用自动切片：装好 ffmpeg 并把 `ffmpeg.exe` 所在目录加进系统 `PATH`，重启程序即可（不需要改任何配置）。

## 五、常见问题

**Q：密钥安全吗？**
密钥明文保存在 `data/config.json`（另有 `config.json.bak` 备份），只在**本机**使用；服务只监听 `127.0.0.1`，不对局域网/公网开放。界面上密钥显示为掩码，不改动即保持原值。不要把 `data/` 目录分享给别人或提交到代码仓库。

**Q：端口被占用？**
程序会从 8787 开始自动往后找可用端口，控制台会打印实际地址。也可以「设置 → 通用」里改端口（改完要重启）。

**Q：任务跑到一半关掉程序会怎样？**
重启后任务会标记为「已中断」，点「重新运行」会从上次完成的步骤继续（转写/润色的中间结果有缓存，不会重复计费）。

**Q：花了钱但失败了怎么办？**
失败任务会带上模型的错误信息、`requestId` 和建议动作。常见原因：密钥错、模型名不对、额度不足、音频超过接口上限、接口不支持 `verbose_json`（程序会自动降级并提示）。

**Q：点「添加工作区」没看到选择窗口？**
系统窗口可能被浏览器盖住，看一下任务栏里的「选择文件夹」窗口；也可能是系统环境拿不到原生窗口（例如没有 zenity 的 Linux），这时程序会自动回退到内置目录浏览器。当前使用的是哪种方式，可以在「设置 → 通用 → 文件夹选择」里看到。

**Q：能多任务并行吗？**
默认一次只跑一个任务（更稳、更好排查）。可以在「设置 → 通用」把并发调到 2–3。

**Q：数据存在哪里？**
`data/` 目录：`config.json`（三个模型 + 工作区列表）、`tasks/<任务id>/`（任务状态、运行日志、中间缓存）。删掉 `data/tasks` 里的旧目录不影响使用。

**Q：会不会改动我的原始音频？**
不会。程序只读输入文件，产物写到交付区。切片产生的临时文件在任务目录的 `tmp/` 下，用完自动清理。

## 六、目录结构

程序全部位于 `meeting-notes-studio/` 文件夹内，双击其中的 `start.bat` 即可启动。

```
meeting-notes-studio/
  start.bat               一键启动
  server/
    index.mjs             启动、端口探测、静态资源与鉴权
    http.mjs              路由 / JSON / SSE / 静态文件
    config.mjs            配置默认值、归一化、脱敏、原子保存
    store.mjs  log.mjs    数据持久化与日志
    api/                  配置、文件浏览、工作区、任务接口
    providers/            OpenAI / Gemini / 百炼 / 模拟模型 / 对话统一入口
    pipeline/             流程解析、转写、润色、纪要、产物渲染、任务队列
    lib/                  时间、文本、Markdown、ffmpeg、系统原生文件夹对话框
  web/                    原生 ESM 前端（hash 路由 + SSE）
  tests/                  单测 + 假模型服务 + 端到端测试
  data/                   运行时生成（已在 .gitignore 中）
```

## 七、开发者

```bash
npm test              # 单元测试 + 端到端测试（会启动本地假模型服务，不联网）
npm run test:unit     # 只跑单元测试
npm run test:e2e      # 只跑端到端测试
node server/index.mjs --no-open   # 启动但不自动开浏览器
```

端到端测试用 `tests/mock-provider.mjs` 伪装了 OpenAI / Gemini / 百炼三套协议，覆盖：全流程、部分流程、文本输入、srt 字幕、百炼 OSS 上传表单顺序、多模态回退、取消、失败重试、SSE 进度、输入校验、原生文件夹选择接口（用注入的假对话框，不会真的弹窗）。

`server/lib/native-dialog.mjs` 的系统对话框实现有独立单测；在 Windows 上还会额外用 PowerShell 解析生成的脚本并加载 WinForms，确认脚本语法与环境可用（不弹窗）。

## 八、已知限制

- 不做说话人分离与角色命名（百炼的 `diarization_enabled` 未开放到界面）。
